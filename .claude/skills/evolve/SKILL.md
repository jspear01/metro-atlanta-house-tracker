# Harness Evolve — 하네스 진화 메커니즘

실제 프로젝트 실행 후 "무엇이 효과적이었고 무엇이 부족했는가"의 델타를 포착해 `.claude/agents/`, `.claude/skills/`, `CLAUDE.md`에 일반화된 원리로 반영한다.

## 진행 절차

### 1단계: 델타 및 실행 흔적 수집
1. `.claude/agents/`, `.claude/skills/`, `CLAUDE.md`(변경 이력 표)를 읽는다.
2. `git log --oneline -- .claude/ CLAUDE.md`로 초기 구성 대비 변경 이력을 확인한다.
3. `_workspace/`가 있으면 최근 실행의 중간 산출물(`02_workflow_verified.json`, `03_*`, `04_qa-verifier_report.md`)을 점검해 오케스트레이터 경로가 우회되지 않았는지, 반복된 실패나 수정 루프가 있었는지 확인한다.
4. 사용자가 이미 피드백을 주지 않았다면 개선하고 싶은 점을 확인한다.

### 2단계: 피드백 분류 및 수정 대상 결정
- **산출물·코드 품질 문제** → 해당 전문 스킬(`.claude/skills/{skill}/SKILL.md`)에 판단 원리와 이유(Why) 추가
- **에이전트 역할·도구·모델 조정** → `.claude/agents/{agent}.md` 수정
- **단계 순서·데이터 전달·실행 모드 조정** → `.claude/skills/metro-atl-orchestrator/SKILL.md` 수정
- **호출(트리거) 누락** → 해당 스킬의 `description`에 사용자 표현 추가

### 3단계: 일반화 및 반영 원칙
1. **특정 사례 과적합 금지**: 단일 사례에 1:1 규칙을 덧붙이지 않고, 왜 그런 문제가 생겼는지 원리 수준으로 일반화해 이유와 함께 적는다.
2. **한 번에 한 항목씩 수정**: 변경 후 곧바로 파일 구조, 참조 일관성, `SKILL.md` 500줄 미만 기준을 확인한다.
3. **언어 일관성 유지**: 기존 하네스 파일에 쓰인 언어(한국어)를 유지한다.

### 4단계: 변경 이력 갱신
`CLAUDE.md`의 **변경 이력** 표에 날짜, 변경 내용, 대상, 사유를 추가하고 사용자에게 포착된 델타와 반영 근거를 보고한다.
